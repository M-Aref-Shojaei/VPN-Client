# Coding Standards

Home: [[00-Index/Home]]

- Shell scripts (`binConfigs/*.sh`): `set -e` where practical, quote all variable expansions,
  functions for anything reused across desktop environments (see existing `detect_desktop_environment`
  pattern in `proxy_set_linux_sh.sh`).
- Backend config (`binConfigs/config.json`, `configPre.json`): keep `configPre.json` as the
  human-edited source of routing/DNS rules; treat `config.json` as generated output — don't hand-edit
  the generated file.
- No secrets (server credentials, subscription URLs) committed in `binConfigs/` — these are runtime
  configs and should be gitignored alongside `bin/`, `guiConfigs/guiNDB.db`, and `guiLogs/`.

## Go core

- Standard library first; justify every dependency that touches traffic, DNS, credentials, or
  update delivery.
- Run `gofmt`, `go test ./...`, and `go vet ./...` for every core change.
- Routing precedence must be deterministic and covered by table tests.
- Empty match lists must never serialize as catch-all rules.
- Persist private state atomically and with owner-only permissions.
- Never classify HTTP status codes as network blocking.

## Flutter application

- Keep platform privilege operations behind `TunnelService`; widgets do not invoke shell commands.
- Capability must be queried and displayed. Never show a false connected state.
- Run `dart format`, `flutter analyze`, and `flutter test`.
- Domain rules use boundary matching: `example.com` matches `api.example.com`, not
  `notexample.com`.
- UI state may contain display metadata; credentials must move to secure storage before release.

## Configuration

- New runtime configuration is generated by `core/configbuilder`; do not hand-edit generated JSON.
- Profile examples use reserved placeholder domains and all-zero identifiers.
- `route.final` remains `direct` for smart-routing mode.
- Every generated config must pass the packaged sing-box version's `check` command.
